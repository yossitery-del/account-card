# החלטות פרטיות — כרטיס חשבון

מסמך מקור אמת לפרטיות, הצפנה, וניסוחים מותרים. Stage 0 — ללא מימוש CSE.

---

## מה מובטח עכשיו (Stage 0 / תשתית)

| נושא | מצב |
|------|-----|
| תעבורה | TLS (HTTPS) |
| אחסון | תשתית Firebase/Google — אבטחה סטנדרטית של ספק הענן |
| גישה לנתונים (עתיד) | Firestore Rules — כרגע **deny-all** עד Stage 1/2 |
| אנליטיקה על תוכן | **אסור** — לא מחובר ולא מתוכנן |
| UID בממשק | **אסור** להציג UID גולמי |

---

## מה אסור להבטיח עכשיו

אין להשתמש בביטויים הבאים **עד מימוש טכני מלא ומאומת**:

- «כמו בנק»
- «גם לנו אין גישה»
- «מוצפן מקצה לקצה» / «E2E encryption»

---

## ניסוחים מותרים (בינתיים)

> «המידע נשמר בתשתית מאובטחת, עם גישה רק למשתתפים הפעילים בכרטיס.»

אם ייושמו שדות מוצפנים בפועל (עתיד):

> «חלק מהשדות הרגישים נשמרים בהצפנה נוספת.»

---

## Encryption Ready Architecture

| רכיב | Stage 0 |
|------|---------|
| `encryptionMode` על כרטיס | ערך `none` — מוכן לשדה |
| הצפנת client-side | **לא ממומש** |
| מבנה שדות | מוכן ל־`ciphertext` / `iv` בעתיד |

### שדות מועמדים להצפנה עתידית

- `accountCards.title`
- `entries.title`
- `entries.note`

### למה סכומים לא מוצפנים בפיילוט הראשון

- חישוב `officialBalance` / `pendingBalanceImpact`
- Firestore Rules ו־Cloud Functions
- Truth Dataset ורגרסיה
- PDF עתידי (אם ייבנה client-side)

### מה נדרש ל«גם לנו אין גישה»

1. Client-side encryption לשדות רגישים
2. מפתח כרטיס (לא רק Google token)
3. מנגנון recovery / אובדן מפתח
4. בדיקות אבטחה + עדכון `PRIVACY_DECISIONS` ו־UI
5. החלטה מפורשת על סכומים (להשאיר גלויים או ארכיטקטורה נפרדת)

## שימוש במידע

| מותר | אסור |
|------|------|
| הרצת המוצר למשתמש | למידת מכונה על תוכן כרטיסים |
| תמיכה טכנית (עתיד, ממוזער) | פרסום / ניתוח מסחרי של תוכן |
| | שליחת תוכן כרטיסים לאנליטיקה (GA, Mixpanel, וכו') |

---

## PDF

PDF **מחוץ לליבת הפיילוט**. אם ייבנה — client-side בלבד, ללא UID, RTL עברי.

---

## מחיקה לצמיתות (עתיד)

- שונה מביטול פעולה (`cancelled` / `void`)
- משתמש יוכל למחוק כרטיס או את כל מידעיו — מימוש Stage 1.1+
